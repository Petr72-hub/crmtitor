# Как запустить CRM в интернете (доступ с телефона и компьютера) + логины/пароли

Ничего платить не обязательно — оба сервиса ниже бесплатны для такого объёма данных.
Понадобится ~25–30 минут (добавился один новый шаг — серверная функция для управления
аккаунтами) и два бесплатных аккаунта: **Supabase** (база данных + логины) и **Vercel**
(сам сайт). Ни один из паролей и ключей ниже вводить в чат Claude не нужно — делаете всё
сами в браузере/терминале, я подготовил только код и инструкцию.

---

## Шаг 1. База данных и аккаунты — Supabase

1. Зайдите на [supabase.com](https://supabase.com) → **Start your project** → войдите через GitHub/email.
2. **New project** → задайте имя (например `mycrm`), придумайте пароль базы данных (сохраните его отдельно,
   он не пригодится в приложении, но нужен для доступа к самой базе), выберите ближайший регион (Frankfurt
   для РФ/СНГ обычно быстрее всего) → **Create new project**. Подождите 1–2 минуты, пока проект поднимется.
3. Слева откройте **SQL Editor** → **New query**. Откройте у себя файл [`supabase/schema.sql`](./supabase/schema.sql),
   скопируйте **всё содержимое**, вставьте в редактор и нажмите **Run**. Это создаст все таблицы и права
   доступа по ролям. Файл безопасно запускать повторно (например, если позже обновите код) — он не
   затирает уже введённые данные.
4. Слева зайдите в **Authentication → Providers → Email** и **выключите** "Allow new users to sign up"
   (в приложении нет формы саморегистрации, но без этой галочки кто угодно, зная адрес вашего сайта,
   теоретически мог бы создать себе аккаунт напрямую через API — лучше сразу закрыть).
5. Там же в **Authentication → Users** нажмите **Add user → Create new user**, впишите email и пароль
   для себя — это будет ваш логин в CRM. Именно первый когда-либо созданный пользователь автоматически
   получает роль **Владелец** (это настроено в `schema.sql`) — только у вас будет право добавлять и
   удалять администраторов и репетиторов. Всех остальных сотрудников добавляете уже не через Supabase,
   а прямо внутри CRM на вкладке «Пользователи» (см. раздел «Как пользоваться дальше» ниже) — но для
   этого сначала нужно выполнить Шаг 2.
6. Зайдите в **Project Settings (⚙️) → Data API**. Скопируйте:
   - **Project URL** (выглядит как `https://xxxxx.supabase.co`)
   - **anon public** ключ (длинная строка в разделе Project API keys)

   Они понадобятся на шаге 4. Это не секретный пароль (он публичный, работает в связке с настроенными
   правилами доступа), но всё равно держите его только в настройках хостинга, а не в открытых местах.

## Шаг 2. Серверная функция управления аккаунтами — Supabase CLI

Кнопки «Добавить сотрудника», «Удалить», «Сбросить пароль» и создание доступа для родителей
работают не напрямую из браузера, а через отдельную защищённую функцию на сервере Supabase —
так безопаснее (подробности в комментарии наверху файла [`supabase/functions/manage-users/index.ts`](./supabase/functions/manage-users/index.ts)).
Её нужно один раз задеплоить через терминал.

1. В папке проекта (`C:\CRM-titor`) выполните:

   ```bash
   npx supabase login
   ```

   Откроется браузер — войдите тем же аккаунтом, что и в Supabase Dashboard.

2. Узнайте **Reference ID** вашего проекта: Supabase Dashboard → **Project Settings → General** →
   поле "Reference ID" (выглядит как `xbhdtglwyowcdhgaxizr`). Затем выполните:

   ```bash
   npx supabase link --project-ref ВАШ_REFERENCE_ID
   ```

3. Задеплойте функцию:

   ```bash
   npx supabase functions deploy manage-users
   ```

   Ключи для базы данных функция получает автоматически от Supabase — вручную ничего вводить не нужно.

## Шаг 3. Код проекта — GitHub

1. Если у вас ещё нет аккаунта — зарегистрируйтесь на [github.com](https://github.com).
2. Создайте новый пустой репозиторий (**New repository**), например `mycrm`.
3. У себя в папке проекта (`C:\CRM-titor`) выполните в терминале:

   ```bash
   git init
   git add .
   git commit -m "MyCRM: первая версия"
   git branch -M main
   git remote add origin https://github.com/ВАШ_ЛОГИН/mycrm.git
   git push -u origin main
   ```

   (файл `.env` с вашими ключами в репозиторий не попадёт — он специально добавлен в `.gitignore`).

## Шаг 4. Публикация сайта — Vercel

1. Зайдите на [vercel.com](https://vercel.com) → войдите через GitHub.
2. **Add New… → Project** → выберите репозиторий `mycrm`, который вы только что запушили → **Import**.
3. Vercel сам определит, что это Vite-проект. Перед деплоем откройте **Environment Variables** и добавьте:
   - `VITE_SUPABASE_URL` = ваш Project URL из шага 1.6
   - `VITE_SUPABASE_ANON_KEY` = ваш anon public ключ из шага 1.6

   Если Vercel предупредит, что переменная с префиксом `VITE_` будет видна в браузере — это ожидаемо
   и безопасно для этих двух значений (см. пояснение в чате), выбирайте вариант **Config**, а не
   «сделать приватной» — иначе сайт не сможет подключиться к базе данных.
4. Нажмите **Deploy**. Через минуту получите ссылку вида `https://mycrm-xxxx.vercel.app` —
   это и есть ваша CRM, доступная из любой точки мира, с телефона и с компьютера, по HTTPS.
5. Откройте эту ссылку, войдите email/паролем, которые создали в шаге 1.5.

### Свой домен (необязательно)

В Vercel: **Project → Settings → Domains** → впишите свой домен (например `crm.вашсайт.ру`) и
подключите его согласно инструкции Vercel (обычно 1–2 записи DNS у вашего регистратора домена).

## Как пользоваться дальше

### Роли

- **Владелец** (вы) — видит и меняет всё, включая Финансы. Только Владелец может добавлять и
  удалять администраторов и репетиторов на вкладке «Пользователи».
- **Администратор** — видит и меняет всё то же самое, что Владелец (Лиды, Учеников, Финансы,
  Аналитику, Контент, Пробное занятие), но не может добавлять/удалять админов и репетиторов —
  только владелец.
- **Репетитор** — видит только своё расписание и назначенных ему учеников; может менять данные
  только в карточке своего ученика; не видит Лиды, Финансы, Аналитику, Пользователей.
- **Родитель** — отдельный вход на `/parent` (не через общую страницу входа), видит только
  карточку своего ребёнка: промежуточные результаты и домашние задания. Ничего больше в системе
  ему не видно — это ограничение задано на уровне базы данных, а не только интерфейса.

### Добавить сотрудника (админа или репетитора)

Вкладка **«Пользователи»** (видна только Владельцу и Администратору) → кнопка «+ Добавить
сотрудника» → укажите роль, имя, email и пароль. Логин и пароль сообщите сотруднику сами.
Добавлять/удалять может только Владелец; Администратор может только менять ставку за урок.

### Дать доступ родителю

Откройте карточку конкретного ученика (вкладка «Ученики» → клик по строке) → вкладка «Доступ
родителя» → «Создать доступ для родителя»: придумайте логин (латиницей) и пароль, сообщите их
родителю. Родитель заходит на `<ваш-сайт>/parent` — например `https://mycrm-xxxx.vercel.app/parent`.

### Забыли пароль

Владелец/Администратор может сбросить пароль сотруднику или родителю прямо в интерфейсе — кнопка
«Сбросить пароль» на вкладке «Пользователи» или в карточке ученика. Свой собственный пароль каждый
меняет на вкладке «Профиль», уже войдя в систему.

### Тёмная тема

Переключатель — внизу бокового меню (🌙/☀️). Выбор сохраняется в браузере каждого сотрудника отдельно.

### Обновление кода

Если попросите что-то доработать — после изменений достаточно сделать `git push`, и Vercel
автоматически передеплоит новую версию за 30–60 секунд. Если менялась именно серверная функция
(`supabase/functions/manage-users`), её нужно передеплоить отдельно командой из Шага 2.3.

## Важно про бесплатные тарифы

- Supabase на бесплатном тарифе «замораживает» проект, если им не пользовались 7 дней подряд —
  зайдите в Dashboard и нажмите «Restore project», это займёт пару минут. Если CRM будет
  использоваться регулярно, это не будет ощущаться.
- Vercel на бесплатном тарифе не имеет ограничений по времени — сайт работает постоянно.
- Если бизнес вырастет (сотни тысяч записей, много одновременных пользователей), оба сервиса
  предлагают платные тарифы от ~$25/мес каждый — но для одной школы/студии бесплатных тарифов
  хватает с большим запасом.
